# 卡片/指纹/密码管理页：添加态时序调整

日期：2026-09-22
涉及仓库：
- 室内机 `/home/leo/workspace/myworkspace/METER/INDOOR/AmyIPSdk`
- 门口机 `/home/leo/workspace/myworkspace/METER/OUTDOOR/app`

## 背景

卡片/指纹/密码三个管理页，向门口机下发"进入管理模式"指令的时机不一致：

| 页面 | Enter 下发时机 | 现状代码 |
|------|---------------|---------|
| 卡片 | 添加态（打开添加 overlay 时） | page_card_manager.c:342 |
| 指纹 | 页面进入 | page_fingerprint_manager.c:718 |
| 密码 | 页面进入 | page_password_manager.c:786 |

门口机侧对应状态：卡片是 `CARD_MODE_MANAGER`（只有刷卡回推 SCAN 依赖它），指纹和密码是 `is_managed`（卡住 Add/Del/SetPerm，Query 不卡）。

密码这条管理模式纯属多余：密码添加完全由室内机自己的键盘 overlay 输入后发 `AddPassword` 完成（page_password_manager.c:610），与门口机管理模式无关。

## 目标

1. 指纹改为与卡片一致：**只有进入添加态才下发 Enter**。
2. 密码**取消管理模式**，用特性宏保留代码路径，便于将来恢复。
3. 卡片与指纹的添加态加 **20 秒无操作定时器**，超时自动退出添加态。
4. 门口机侧同步适配，使列表内的删除/改权限等操作在新时序下仍然可用。

## 设计

### 1. 室内机 · 指纹页

- `Amy_lv_page_enter`（:718-721）：去掉 `EnterFingerManage` 下发，保留 `finger_query_send()`。门口机 Query 不校验管理模式（fingerprint_service.c:692-695），列表可正常拉取。
- `finger_add_overlay_create()`（:597）：新增下发 `EnterFingerManage`（req 构造照抄 page_card_manager.c:334-343）；创建完 overlay 后启动 `FINGER_ADD_IDLE_TIMEOUT_MS = 20000` 定时器。
- `finger_add_click`（:187）：保持"先 `finger_add_overlay_create()` 再发 `AddFinger`"，顺序即 Enter → AddFinger，满足门口机"必须先 is_managed 才收 Add"。
- `fingerprint_event_cb` 的 `COMM_FINGER_PUSH_ADD`（:136）：`lv_timer_reset` 定时器（非空时）。
- `finger_add_overlay_destroy()`（:650）：删除定时器，下发 `ExitFingerManage`，再删 overlay。
- `Amy_lv_page_quit`（:727-741）：**保留原有的 `ExitFingerManage` 下发不变**，额外增加"删除定时器"。

### 2. 室内机 · 卡片页

- `add_data_overlay_create()`（:329）：已下发 `EnterCardManage`，新增启动 `CARD_ADD_IDLE_TIMEOUT_MS = 20000` 定时器。
- `card_event_cb` 的 `PUSH_OP_SCAN_CARD`（:109）：定时器为空则直接 return（已不在添加态，忽略迟到的 SCAN，不下发 `AddCard`）；否则 `lv_timer_reset` 后按原有逻辑下发 `AddCard`。
- `add_data_overlay_destroy()`（:394）：删除定时器，下发 `ExitCardManage`，再删 overlay。
- `Amy_lv_page_quit`（:725）：**保留原有的 `ExitCardManage` 下发不变**，额外增加"删除定时器"。

### 3. 室内机 · 密码页（宏开关）

- 新增特性宏 `PASSWORD_ADMIN_MODE_ENABLE`，定义在 `common/password_common_net_proto.h`：

  ```c
  #ifndef PASSWORD_ADMIN_MODE_ENABLE
  #define PASSWORD_ADMIN_MODE_ENABLE 0
  #endif
  ```

  用 `#ifndef` 包住默认值，便于编译期 `-D` 覆盖且不会触发宏重定义告警。两个仓库各有一份同名同内容的协议镜像头，宏放此处可让"这个开关管的是密码管理协议"一目了然，两边也好对齐。

- `Amy_lv_page_enter`（:786）的 `EnterPasswordManage` 与 `Amy_lv_page_quit`（:808）的 `ExitPasswordManage` 用 `#if PASSWORD_ADMIN_MODE_ENABLE` 包起来。Query 不受影响，两种情况都照发。
- 默认值为 0，即当前行为为"密码不使用管理模式"；翻宏即可恢复原时序。

### 4. 门口机适配

- `password_service.c:597-605` 的 `if (!managed) { ...; return false; }` 用 `#if PASSWORD_ADMIN_MODE_ENABLE` 包起来。`is_managed` 字段、Enter/Exit 处理器、30s 超时线程全部原样保留——宏关闭时无人给 `is_managed` 置位，这套机制自然休眠，无需额外改动。
- `fingerprint_service.c:698-705` 同样的 `if (!managed) return false;` **直接删除**，不用宏包裹。这不是取消一项功能，而是让指纹的 Del/Clear/SetPerm 与卡片一致（`card_swipe_handle_cmd` 本来就只校验 host_id，:857-905）。按新时序，管理模式只在添加态成立，若保留该校验，用户在列表里点删除/全部删除/改权限会直接失败。删除后 `is_managed` 仍被 Enter/Exit、`on_finger_touch`、超时刷新引用，不会产生未使用告警。
- 门口机 30s 管理模式超时（`CARD_SWIPE_MANAGER_TIMEOUT_S` / `FINGER_MANAGER_TIMEOUT_S` / `PASSWORD_MANAGER_TIMEOUT_S`）保持不变，作为室内机定时器之外的兜底。
- 卡片侧无需改动。
- `fingerprint_service.c` 的 `handle_add()`（:283）在调用 `fingerprint_enroll()` 前先 `fingerprint_set_work_mode(FINGER_MODE_MANAGER)`。原因：室内机的异步发送是每次 send 起一个新线程（sat_ipcamera_ctrl.c:63-77），`EnterFingerManage` 与紧跟着的 `AddFinger` **没有先后顺序保证**，不能依赖 Enter 已生效。而 `FINGER_MODE_MANAGER` 的作用正是抑制触摸走门禁验证流程（mgr_fingerprint_service.c:440-444、540-577），否则触摸线程的 `fingerprint_verify()` 会与录入争抢传感器。卡片页不存在这个问题——Enter 与 AddCard 之间隔着用户刷卡的时间。

### 5. 定时器实现

定时器语义：**进入添加态时启动，每收到一次对应推送（卡片为 SCAN、指纹为 `PUSH_ADD`）就重置为完整 20 秒；连续 20 秒没有推送则超时退出添加态。** 即"有操作就续期，无操作 20 秒就退出"。

使用 LVGL 定时器，沿用 page_admin.c:201 的既有写法：

- 创建：`lv_timer_create(cb, MS, NULL)`，指针存页面 ctx。
- 重置：`lv_timer_reset(t)`（share/lvgl/src/misc/lv_timer.h:155）。
- 超时回调：先把 ctx 里的指针置 NULL，再 `lv_timer_del(t)`，然后走"退出添加态"逻辑。
- 删除定时器统一判断非空，避免重复删除。

不抽公共工具函数：两个页面超时后要做的事各不相同（拆各自的 overlay、发各自的 Exit 指令），抽象收益有限。

Exit 指令的两条下发路径：

1. 关闭添加 overlay（用户点 overlay 返回键、或 20s 超时触发的销毁）——新增。
2. 离开页面（`Amy_lv_page_quit`）——沿用原有行为，不动。

## 边界情况

1. **指纹录入超过 20s**：`fingerprint_enroll()` 阻塞门口机服务线程（fingerprint_service.c:288），录入过程中不向室内机推送任何中间消息。若一次录入耗时超过 20s，室内机会在录入途中销毁 overlay 并下发 Exit；该 Exit 在门口机侧需排队等服务线程从 enroll 返回后才生效。结果是指纹实际录入成功，但室内机添加态已退出。录入完成后的 `PUSH_ADD` 到达时 overlay 已不存在，只走 `finger_query_send()` 刷新列表，不做动画，不会出错。
2. **指纹页浏览期间触摸门口机传感器**：改动后 `is_managed` 仅在添加态为真，因此在列表页触摸传感器会被 `on_finger_touch`（:427）当作普通验证处理，门口机播放"验证成功"提示音。改动前整个页面处于管理模式、此情况被忽略。这是本次时序调整的必然副作用。
3. **离页面时仍处于添加态**：添加 overlay 覆盖全屏且自带返回键，正常无法点到页面返回键，仅 standby 自动跳转可能触发。此时 `Amy_lv_page_quit` 仍会下发 Exit。同时该函数已通过 `Amy_event_cb_register(..., NULL)` 注销事件回调，迟到的推送不会打到已销毁的页面。
4. **关闭 overlay 后离开页面会连发两次 Exit**：门口机两处发 Bi4 提示音（card_swipe.c:684、fingerprint_service.c:494）。这是两条下发路径叠加的既定结果。
5. **超时后迟到的卡片 SCAN**：由"定时器为空即忽略"的守卫挡掉，不会误添加。
